# Public Standing Review Synthesis

**Review date:** 2026-05-08
**Review label:** baseline after root/staging story-alignment promotion
**Compared to:** 2026-05-07 public surface audit

## Executive Read

The root/staging story-alignment sprint did the right thing in source: README
and landing metadata now describe iHomeNerd as a local AI home brain instead of
leading with staging mechanics. The public web, however, has not caught up.
Live root still tells the older smart-home intelligence story, and live staging
still serves the pre-promotion preview-heavy build.

The public standing therefore improves only for visitors who reach the updated
GitHub README or future deployed staging build. A cold visitor who starts at
`ihomenerd.com` still sees the old mismatch.

## What Outsiders Understand Correctly

- iHomeNerd is early and preview-stage.
- The project is related to local/private AI at home.
- Docker is the current early-adopter path.
- VM and live image are not ready as polished mainstream paths.
- The repo has real docs and recent activity.

## What Outsiders Still Misread

- The live root page can still make iHomeNerd sound like a smart-home product
  intelligence app rather than a local AI home brain.
- The deployed staging page still overuses `public preview` and old staging
  reassurance language.
- GitHub still makes openness/legal status unclear because there is no license.
- GitHub metadata still makes the project look less mature than its docs and
  commit history suggest.

## Score Movement

- Category clarity improved in repo-controlled source.
- Root/staging consistency has not improved for live visitors yet.
- Trust/legal clarity improved slightly because the unsupported `Open core`
  claim was removed.
- Repo credibility remains limited by missing metadata, releases, screenshots,
  and license.

## Wrong-Inference Movement

- `Virtual home staging`: improved in source, still needs live deployment.
- `Private admin/staging surface`: improved in source, still visible in live
  staging HTML.
- `Open source/open core`: improved by removing overclaim, still unresolved
  until license decision.
- `Abandoned/hype`: open because GitHub metadata remains weak.

## Top Three Next Actions

1. Deploy or replace the live root/staging public pages so visitors see the
   promoted local AI home brain story.
2. Run GitHub trust-surface cleanup: license decision, repo description,
   homepage, topics, and one screenshot/demo signal.
3. Add SEO basics: `robots.txt`, `sitemap.xml`, canonical URL decision, and
   social preview metadata.

## Notes For Next Review

- Separate source-state improvements from live-public improvements.
- Re-score root/staging consistency only after the deployed root and staging
  pages reflect promoted source.
- Keep license/opening status as a P0 wrong-inference item until decided.
